Aula 1 | 13/10 | Node.js, npm e instalação global × local — jogar na quinta, 19h00 (retomada)

Questão 1 | 20 segundos

O que o comando npm install chalk faz no projeto?

OpçãoAlternativaStatus
AInstala o chalk em todos os projetos do computadorIncorreta
BBaixa o pacote para a node_modules e o anota em dependenciesCORRETA
CCria um arquivo chamado chalk.jsIncorreta
DApaga o package.json e começa outroIncorreta

Comentário docente: O npm install consulta o registro, baixa o pacote para node_modules, anota a versão em dependencies do package.json e atualiza o package-lock.json. Instalar em todos os projetos seria a opção global (-g).

Questão 2 | 20 segundos

Qual arquivo guarda a "identidade" do projeto Node (nome, versão, scripts e dependências)?

OpçãoAlternativaStatus
Aindex.jsIncorreta
Bnode_modulesIncorreta
C.gitignoreIncorreta
Dpackage.jsonCORRETA

Comentário docente: O package.json é o manifesto do projeto. O index.js é código; a node_modules é a pasta onde os pacotes ficam (e é recriada com npm install); o .gitignore diz ao Git o que não versionar.

Questão 3 | 30 segundos

O que significa "chalk": "^4.1.2" no package.json?

OpçãoAlternativaStatus
AAceita a 4.1.2 ou qualquer 4.x mais nova, mas nunca a versão 5CORRETA
BExige exatamente a versão 4.1.2Incorreta
CAceita qualquer versão do chalkIncorreta
DAceita só as versões 4.1.xIncorreta

Comentário docente: O circunflexo (^) libera atualizações compatíveis dentro da mesma versão MAIOR. A versão exata seria "4.1.2" e o til (~4.1.2) aceitaria só 4.1.x. É por isso que o chalk@4 ficou "preso" na versão 4.

Questão 4 | 30 segundos

Em qual situação a instalação global (npm install -g) faz mais sentido?

OpçãoAlternativaStatus
AUma biblioteca que o seu index.js importa com requireIncorreta
BTodos os pacotes de todos os projetos, para economizar tempoIncorreta
CUma ferramenta de linha de comando de uso pessoal, usada em todos os projetosCORRETA
DCriar o package.json do projetoIncorreta

Comentário docente: Pacotes globais ficam fora do package.json e não viajam com o projeto. Por isso o que o código importa deve ser local; global fica para utilitários pessoais, com parcimônia.

Questão 5 | 30 segundos

Em qual seção do package.json deve ficar o nodemon, usado só enquanto você desenvolve?

OpçãoAlternativaStatus
AdependenciesIncorreta
BdevDependenciesCORRETA
CscriptsIncorreta
DmainIncorreta

Comentário docente: Ferramentas de desenvolvimento entram em devDependencies (npm install --save-dev nodemon ou -D). Em produção, npm install --omit=dev ignora essa seção.

Questão 6 | 20 segundos

Como executar uma ferramenta de linha de comando uma única vez, sem deixá-la instalada?

OpçãoAlternativaStatus
Anpm init -yIncorreta
Bnpm uninstallIncorreta
Cnpm auditIncorreta
DnpxCORRETA

Comentário docente: O npx baixa o pacote de forma temporária, executa o comando e não o registra no projeto. O npm init -y só cria o package.json; uninstall remove e audit procura vulnerabilidades.

Aula 2 | 15/10 | Módulos: CommonJS × ESM — jogar na quinta, 21h35 (fechamento da aula ao vivo)

Questão 7 | 20 segundos

Qual par de palavras-chave pertence ao CommonJS?

OpçãoAlternativaStatus
Aimport e exportIncorreta
Bfetch e awaitIncorreta
Crequire e module.exportsCORRETA
DsetTimeout e setIntervalIncorreta

Comentário docente: require/module.exports é o sistema clássico do Node (CommonJS). import/export é o ESM, o padrão da linguagem. As outras duas opções são de assincronia e tempo.

Questão 8 | 20 segundos

No ESM do Node, o que é obrigatório ao importar um arquivo seu?

OpçãoAlternativaStatus
AA extensão do arquivo, como .jsCORRETA
BAspas simplesIncorreta
CO ponto e vírgula no fimIncorreta
DO prefixo node:Incorreta

Comentário docente: Em ESM o Node não completa o nome sozinho: import { perguntas } from "./perguntas.js". Sem a extensão aparece ERR_MODULE_NOT_FOUND. O prefixo node: é só para módulos nativos.

Questão 9 | 30 segundos

Depois de npm install chalk@latest, o require("chalk") passou a dar TypeError ... (reading 'yellow'). Por quê?

OpçãoAlternativaStatus
AFaltou rodar npm installIncorreta
BO chalk novo é um módulo ESM e, via require, a função vem embrulhada em .defaultCORRETA
CO nome do pacote foi digitado erradoIncorreta
DO Node não está instaladoIncorreta

Comentário docente: Se faltasse o pacote o erro seria Cannot find module. Aqui o pacote carregou, mas por ser ESM veio dentro de .default; chalk.bold ficou undefined. O conserto certo é assumir ESM ("type": "module" + import).

Questão 10 | 30 segundos

Como declarar que um projeto inteiro usa ESM?

OpçãoAlternativaStatus
A"main": "module" no package.jsonIncorreta
Bnpm install esmIncorreta
CRenomear a pasta para esmIncorreta
D"type": "module" no package.jsonCORRETA

Comentário docente: O campo "type" define como o Node trata os arquivos .js. Também dá para declarar arquivo a arquivo com .mjs (ESM) e .cjs (CommonJS).

Questão 11 | 30 segundos

Qual afirmação sobre export default está correta?

OpçãoAlternativaStatus
ASó pode haver um por arquivo e quem importa escolhe o nomeCORRETA
BPode haver vários no mesmo arquivoIncorreta
CExige importar com chavesIncorreta
DSó funciona dentro de funçõesIncorreta

Comentário docente: O default é a exportação principal do arquivo (uma só) e se importa sem chaves, com o nome que você quiser. As exportações nomeadas podem ser várias e se importam com chaves e o mesmo nome.

Questão 12 | 30 segundos

No ESM não existe __dirname. Como obter a pasta do arquivo atual?

OpçãoAlternativaStatus
Arequire.mainIncorreta
Bprocess.dirIncorreta
Cpath.dirname(fileURLToPath(import.meta.url))CORRETA
D__dirname funciona igualIncorreta

Comentário docente: import.meta.url é o endereço do módulo; fileURLToPath o converte em caminho e path.dirname tira o nome do arquivo. É o preço de o ESM ser um padrão que também funciona no navegador.

Aula 3 | 16/10 | Depuração e debugger no VS Code — jogar na retomada da próxima aula ou como revisão no AVA

Questão 13 | 20 segundos

O que faz um breakpoint?

OpçãoAlternativaStatus
AApaga a linha marcadaIncorreta
BComenta o código abaixo deleIncorreta
CReinicia o programa do começoIncorreta
DPausa a execução na linha marcada para você inspecionar o estadoCORRETA

Comentário docente: O breakpoint não altera o código: ele só diz ao debugger onde parar. Com o programa pausado, Variables, Watch e Call Stack mostram o que está acontecendo naquele instante.

Questão 14 | 20 segundos

Qual atalho executa o Step over no VS Code (Windows)?

OpçãoAlternativaStatus
AF5Incorreta
BF10CORRETA
CF11Incorreta
DShift + F11Incorreta

Comentário docente: F10 = step over (executa a linha e passa para a próxima), F11 = step into (entra na função), Shift+F11 = step out (sai da função) e F5 = continue.

Questão 15 | 30 segundos

Qual painel do debugger mostra "quem chamou quem" até a linha pausada?

OpçãoAlternativaStatus
AWatchIncorreta
BVariablesIncorreta
CCall StackCORRETA
DBreakpointsIncorreta

Comentário docente: A Call Stack lista as funções em execução, da mais recente para a mais antiga — essencial para entender de onde veio um erro. Watch acompanha expressões; Variables mostra valores; Breakpoints lista os pontos de parada.

Questão 16 | 30 segundos

Um breakpoint condicional com a condição i === 6 faz o debugger:

OpçãoAlternativaStatus
AParar só quando i valer 6 (a 7ª volta do laço)CORRETA
BParar exatamente 6 vezesIncorreta
CParar sempre na linha 6 do arquivoIncorreta
DIgnorar o laço inteiroIncorreta

Comentário docente: A condição é um filtro: o debugger só pausa nas passagens em que ela é verdadeira. Em um laço de 60 voltas, isso evita apertar F5 dezenas de vezes.

Questão 17 | 30 segundos

No painel Variables, resposta aparece como "3" (com aspas) e correta como 3. O que isso indica?

OpçãoAlternativaStatus
AAs duas são números iguaisIncorreta
Bresposta é texto e correta é número; === entre os dois dá falseCORRETA
Cresposta é undefinedIncorreta
Dcorreta é um arrayIncorreta

Comentário docente: As aspas denunciam uma string. O prompt sempre devolve texto, e "3" === 3 é falso porque o === compara valor e tipo. A correção é converter com Number(resposta).

Questão 18 | 30 segundos

Para o debugger parar exatamente na linha que lança um erro, você marca no painel Breakpoints:

OpçãoAlternativaStatus
AHit CountIncorreta
BLogpointIncorreta
CUncaught ExceptionsCORRETA
DskipFilesIncorreta

Comentário docente: Com "Uncaught Exceptions" ligado, o debugger pausa na linha do erro com o estado intacto (Variables e Call Stack). Hit Count conta passagens; Logpoint imprime sem pausar; skipFiles evita entrar em arquivos internos.
