2. Como conduzir a gravação

  • Grave em blocos. Cada bloco do roteiro é um "take" independente (de 3 a 25 min). Se errar feio, regrave só o bloco — não o vídeo inteiro. Na edição você junta os blocos.
  • Abra cada bloco com uma frase-âncora (ex.: "Bloco 6: vamos construir o Quiz da Copa") e diga o minuto-alvo; isso ajuda a localizar o corte e a criar os capítulos.
  • Diga o que digita. Quem assiste não vê seu teclado: fale "npm espaço install espaço prompt-sync" na primeira vez e depois só o comando.
  • Espere 2 segundos depois de cada comando antes de falar do resultado; deixe a saída aparecer inteira na tela.
  • Cursor como ponteiro: circule/aponte o que está explicando. Dê zoom (Ctrl + = no editor) em trechos pequenos.
  • Pausas pedagógicas ⏸: nos pontos marcados, diga "pause o vídeo e faça", mostre na tela o cartão ⏸ SUA VEZ e deixe ~5 s de silêncio (você corta e ajusta na edição).
  • Se errar um comando: não finja que nada aconteceu — erros reais são didáticos. Se for só tropeço de fala, pare 3 s, diga "vou repetir" e refaça a frase; corte na edição.
  • Não leia os slides. O slide é o apoio; a fala do roteiro é uma referência natural, não um texto para decorar.
  • Ritmo: 140–150 palavras por minuto. Se um bloco estourar, corte a demonstração opcional (marcada como ⭐ no roteiro), nunca o exercício guiado.

00:08–00:14Node: o que é, REPL e Node × navegador (slides 5–6)

Na telaSlides 5 e 6; depois o terminal.
O que falar:"Node.js é um ambiente de execução: roda JavaScript fora do navegador, direto no computador. É a mesma linguagem das semanas anteriores; muda o palco: em vez de página, o terminal. E por que importa? O React do Módulo 2 roda sobre Node — npm create vite, npm install, npm run build são todos Node."
node
> 2 + 2
> typeof window
> typeof process
> .exit

node -e "console.log(2 + 2)"
Ao digitar:"Reparem: typeof window dá undefined — no Node não existe janela nem DOM. Já typeof process dá object: o Node tem recursos próprios. O modo interativo, o REPL, serve para testes rápidos. O trabalho de verdade fica em arquivos .js."
Pergunta: O que o Node tem que o navegador não tem, e vice-versa? Resposta esperada: Node: process, fs, require; navegador: window, document, DOM, localStorage.

00:14–00:22Gerenciadores de pacotes, npm e package.json (slides 7–10)

Na telaSlides 7, 8, 9 e 10. Em 1 minuto, abra npmjs.com e pesquise chalk (mostre downloads semanais, versões e o repositório).
O que falar:"Um pacote é código pronto que alguém publicou. Um gerenciador de pacotes busca, baixa, guarda a versão certa e resolve as dependências das dependências. O npm é o padrão e já vem com o Node; existem o yarn e o pnpm — fazem o mesmo trabalho, mudam o comando e o arquivo de lock. Regra de ouro: um gerenciador por projeto. O coração do projeto é o package.json: nome, versão, scripts e dependências. Ele nasce com npm init -y. Duas seções importam: dependencies — o que o código precisa para rodar — e devDependencies — o que só usamos para desenvolver."
Pergunta: Por que não basta copiar os arquivos da biblioteca para a pasta? Resposta esperada: Sem versão registrada, sem as dependências dela, cada máquina fica diferente — o "na minha máquina funciona".
SegurançaDiga em voz alta: confira nome, downloads e mantenedor antes de instalar; a IA às vezes inventa nomes de pacote.

00:22–00:27Versões (semver), lock e npm install por dentro (slides 11–12)

Na telaSlides 11 e 12.
O que falar:"Versão tem três números: MAIOR, MENOR, CORREÇÃO. O circunflexo em ^4.1.2 aceita qualquer 4.x acima, nunca o 5; o til aceita só 4.1.x. O package-lock.json congela as versões exatas de tudo o que foi instalado — ele vai para o Git. A pasta node_modules é pesada e recriável: não vai para o Git, vai no .gitignore, e é refeita com npm install sem nome. O npm install de um pacote faz quatro coisas: consulta o registro, baixa para node_modules, anota no package.json e grava o lock."
Pergunta: Se eu apagar a node_modules, perco o projeto? Resposta esperada: Não: npm install recria a pasta a partir do package.json + lock.

Código que você digita (versão enxuta; o comentado está no gabarito)

const promptSync = require("prompt-sync");
const prompt = promptSync();
const chalk = require("chalk");          // depois do npm install chalk@4

function verificar(resposta, correta) {
  return Number(resposta) === correta;
}

function mensagemFinal(acertos, total) {
  return `Você acertou ${acertos} de ${total}! 🏆`;
}

console.log(chalk.bold.yellow("=== QUIZ DA COPA 2026 ==="));
let acertos = 0;

for (let i = 0; i < perguntas.length; i++) {
  const q = perguntas[i];
  console.log(chalk.cyan(`\n${i + 1}) ${q.pergunta}`));
  q.opcoes.forEach(function (opcao, indice) {
    console.log(`   ${indice + 1}. ${opcao}`);
  });
  const resposta = prompt("Sua resposta (1-4): ");
  if (verificar(resposta, q.correta)) {
    console.log(chalk.green("✅ Acertou!"));
    acertos++;
  } else {
    console.log(chalk.red(`❌ Errou! A resposta certa era a opção ${q.correta}.`));
  }
}

console.log(chalk.bold.yellow("\n" + mensagemFinal(acertos, perguntas.length)));
Fechamento do exercício:"Pronto: um programa Node de verdade, com dependências, script e que qualquer pessoa reconstrói com npm install. Repare no que viajou com o projeto: o package.json e o lock — a node_modules, não."
⏸ Pausa para o aluno⏸ Sua vez no minuto 00:44 (rodar) e 00:50 (teste do clone). Mostre na tela o cartão e deixe ~5 s.
Se der erradoQuiz sempre erra → faltou Number(). Cannot find module 'prompt-sync' → esqueceu o npm install ou está na pasta errada (pwd). Texto sem cor → esqueceu o require("chalk"). PowerShell bloqueando → troque para cmd/Git Bash.

00:52–00:59Instalação local × global e quando usar cada (slides 16–17)

Na telaSlides 16 e 17; terminal com a pasta do Ex1.
npm ls --depth=0
npm ls -g --depth=0
npm root -g
O que falar:"Até agora tudo o que instalamos foi local: vai para a node_modules do projeto e fica anotado no package.json. Existe também o global, com -g: instala uma ferramenta de linha de comando para a máquina inteira, mas não aparece no package.json — não viaja com o projeto. O sintoma clássico: funciona no seu computador e quebra no do colega. Regra de bolso: o que o código importa é local, em dependencies; ferramenta de desenvolvimento é local com -D; comando de uso único é npx; global só para utilitário pessoal."
Pergunta: O chalk pode ser instalado com -g para o meu require achá-lo? Resposta esperada: Não: o require procura na node_modules do projeto; global serve para comandos, não para bibliotecas.

4. Plano B e pontos de atenção

  • Sem internet na hora de gravar: aqueça o cache do npm antes e use npm install --prefer-offline; se não houver jeito, use a pasta gabarito (traz package-lock.json) e explique o que o comando faria.
  • Erro inesperado ao vivo: leia a mensagem inteira em voz alta — é conteúdo da semana. Só corte se o erro for de ambiente (e não de conceito).
  • Seu Node é o 20.18.0: o chalk@4 funciona em qualquer versão; a diferença só aparece na quinta (ERR_REQUIRE_ESM no seu Node × TypeError nos alunos), e o guia ensina a reproduzir o erro dos alunos com node --experimental-require-module.
  • Tempo estourando: encurte o Bloco 4 (conceitos de gerenciadores) e o Bloco 9; nunca o teste do clone nem o nodemon local × global.
